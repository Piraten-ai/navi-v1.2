It runs on NVIDIA Jetson hardware (Nano 8GB, Orin NX 16GB) but also supports lightweight development mode on any laptop.Core Philosophy"When satellites fail, we survive" - The system is designed to operate completely offline with:No internet dependencyFull functionality without cloud servicesPrivacy-first architecture (mental health data never leaves the vessel)Arctic-specific optimizations (low light, high latitude, ice navigation)System Motto"Tools for Amundsen" - Named after Roald Amundsen, the first to reach the South Pole, emphasizing tools for extreme environments with minimal external support.Key Characteristics100% Offline-First: All AI inference, database, storage localProduction-Ready: Hardened error handling, logging, securityModular Design: 6 independent AI modules work togetherReal-Time: WebSocket-based live data streamingPrivacy-Centric: Mental health data stays encrypted and localBattle Mode: Dark red theme optimized for night vision connection managementRoute handlers for all modulesStartup/shutdown lifecycle managementReal-time data broadcastingKey Components:ConnectionManager Class```pythonclass ConnectionManager:    """Manages WebSocket connections for real-time updates."""        Methods:    - connect(websocket) → bool      * Accepts WebSocket, registers in active_connections      * Returns False if max connections reached      * Logs connection event        - disconnect(websocket) → None      * Removes from active_connections      * Logs disconnection event        - broadcast(message: dict) → None      * Sends to all connected clients      * Handles disconnection cleanup      * Logs failures        - send_personal(message, websocket) → None      * Sends to specific client      * Disconnects on failure        - get_connection_count() → int      * Returns active connection count      * Thread-safe via asyncio.Lock```Background Tasks:```pythonasync def _nmea_broadcast_loop()    - Polls NMEA GPS module every cycle    - Broadcasts to WebSocket clients if valid data    - Broadcasts to Redis pub/sub    - Logs data receptionasync def _signalk_broadcast_loop()    - Reads from Signal K client    - Parses navigation/environment data    - Broadcasts to WebSocket clients    - Broadcasts to InfluxDB for time-series storage```Lifespan Context Manager```python@asynccontextmanagerasync def lifespan(app: FastAPI)    - Initialize all modules    - Start background broadcast tasks    - Start NMEA/Signal K modules    - Verify system health    - (yield for app running)    - Graceful shutdown    - Cancel broadcast tasks    - Stop modules    - Close WebSocket connections```Route Handlers (partial SENSOR INTEGRATION MODULESNMEA GPS ModuleFile: `backend/app/modules/nmea_gps.py` (309 lines)Purpose: Read and parse NMEA sentences from GPS serial portNMEA Standard:```Protocol: NMEA 0183Baud Rate: 4800 (standard)Format: ASCII text, LF/CR terminatedSentences: GGA, RMC, GSA, HDT, VTG, etc.Example Sentences:$GPGGA,123519,4807.038,N,01131.000,E,1,08,0.9,545.4,M,46.9,M,,*47$GPRMC,123519,A,4807.038,N,01131.000,E,022.4,084.4,230394,003.1,W*6A$GPHDT,123519,45.0,T*1E```Data Structure:```pythonclass NMEAData:    - latitude: float    - longitude: float    - speed: float (knots)    - heading: float (degrees true)    - altitude: float (meters)    - timestamp: str (ISO)    - satellites: int (count)    - quality: str ("fix", "no_fix", etc.)    - raw: str (original sentence)```Implementation:```pythonclass NMEAGPSModule:    def __init__():        self.running = False        self.serial_port: serial.Serial = None        self.current_data = NMEAData()        self._read_task: asyncio.Task = None        async def start():        - Open serial port (settings.NMEA_SERIAL_PORT)        - Set baud rate (settings.NMEA_BAUD_RATE)        - Create read task        - Start polling sentences        async def _read_loop():        while self.running:            try:                line = self.serial_port.readline()                sentence = pynmea2.parse(line)                                # Extract data based on sentence type                if isinstance(sentence, pynmea2.GGA):                    self.current_data.latitude = sentence.latitude                    self.current_data.longitude = sentence.longitude                    self.current_data.altitude = sentence.altitude                    self.current_data.satellites = sentence.num_sats                elif isinstance(sentence, pynmea2.RMC):                    self.current_data.speed = sentence.speed_knots                    self.current_data.timestamp = sentence.datetime                elif isinstance(sentence, pynmea2.HDT):                    self.current_data.heading = sentence.heading                                self.current_data.timestamp = datetime.now(timezone.utc)                            except Exception as e:                logger.error(f"NMEA parse error: {e}")        async def stop():        - Stop read task        - Close serial port        - Clean shutdown        def get_data() → dict:        return self.current_data.to_dict()        def get_status() → dict:        return {            "running": self.running,            "has_fix": self.current_data.is_valid(),            "last_update": self.current_data.timestamp,            "serial_port": settings.NMEA_SERIAL_PORT        }```Mock Mode (for testing without GPS):```self._mock_latitude = 78.2232  # Svalbardself._mock_longitude = 15.6267self._mock_heading = 45.0self._mock_speed = 5.5# Returns synthetic but realistic data```Error Handling:Port not found: Falls back to mockParse errors: Log, continue---NMEA2000 GPS ModuleFile: `backend/app/modules/nmea2000_gps.py` (313 lines)Purpose: Read GPS position data from CAN bus using NMEA2000 protocol (PGN 129025/129029)NMEA2000 Standard:```Protocol: NMEA2000 (CAN bus based)Interface: SocketCAN (Linux) - useRef<WebSocket | null>(null)  const reconnectTimeoutRef = useRef<number | null>(null)  const reconnectAttempts = useRef(0)    const connect = useCallback(() => {    try {      const ws = new clearTimeout(reconnectTimeoutRef.current)      }      if (wsRef.current) {        wsRef.current.close()      }    }  }, [connect])    return { lastMessage, sendMessage, isConnected, Backend Won't StartSymptom: `ERROR Could not connect to database`Causes & Solutions:```- PostgreSQL not running  → docker-compose ps | grep postgres  → docker-compose restart postgres- Wrong DATABASE_URL in .env  → Check: postgresql://user:pass@postgres:5432/dbname  → Verify credentials in .env- Port already in use  → docker ps | grep 8000  → docker kill [container-id]- Ollama not loaded model  → docker exec aads-navi-ollama ollama list  → docker exec aads-navi-ollama ollama pull llama3.2```2. WebSocket Connection FailedSymptom: Frontend shows "Not connected to Signal K"Causes & Solutions:```- Backend WebSocket not accepting connections  → Check backend logs: docker-compose logs backend  → Verify WS_MAX_CONNECTIONS not exceeded  → Restart backend: docker-compose restart backend- Frontend using wrong WS_URL  → Check .env: VITE_WS_URL=ws://localhost:8000/ws  → For Jetson: VITE_WS_URL=ws://[jetson-ip]:8000/ws- Port 8000 not exposed  → Check docker-compose.yml: ports: ["8000:8000"]```3. NMEA GPS Not Receiving DataSymptom: Dashboard shows 0, 0 coordinatesCauses & Solutions:```- Serial port not available  → Check: ls -la /dev/ttyUSB*  → Set NMEA_SERIAL_PORT=/dev/ttyUSB0- Baud rate mismatch  → Standard NMEA: 4800 baud  → Check GPS device: 4800, 9600, 19200, 38400  → Set NMEA_BAUD_RATE=4800 in .env- Mock mode enabled  → Check: NMEA_MOCK_DATA=false in .env  → Should use real GPS for production- GPS device not sending data  → Verify serial connection: cat /dev/ttyUSB0  → Check GPS power and antenna```4. Ollama Inference SlowSymptom: Chat responses take 30+ secondsCauses & Solutions:```- Using CPU instead of GPU  → Check: docker exec aads-navi-ollama nvidia-smi  → If no GPU: docker build requires --build-arg CUDA_ARCH- Model too large for available VRAM  → Development: Use llama3.2:1b (1GB)  → Production: Use llama3.2 (7B, requires 8GB+)  → Check: OLLAMA_MODEL in .env- Too many concurrent requests  → Implement: Request queueing (planned feature)  → Limit: WS_MAX_CONNECTIONS- InfluxDB writes blocking inference  → Async writes should prevent blocking  → Check: backend logs for exceptions```5. Database Disk FullSymptom: `ERROR No space left on device`Causes & Solutions:```- Log files growing too large  → Check: du -sh logs/  → Solution: Enable log rotation  → docker exec aads-backend rm logs/*.1 logs/*.2- InfluxDB retention not working  → Check: INFLUXDB_RETENTION=30d in .env  → Verify: InfluxDB bucket settings  → Manually purge: influx bucket delete --name aads_metrics- Video clips not cleaned up  → Check: MinIO bucket size  → Delete old clips manually  → Implement: Cleanup script (planned)- PostgreSQL bloat  → Run: VACUUM ANALYZE  → docker exec aads-postgres vacuumdb -U aads -d aads -z```Monitoring & Health ChecksHealth Endpoints```GET /health  Returns: { "status": "ok", "timestamp": "...", "services": {...} }  GET /api/v1/status  Returns: Pure function for unit tests and later integration with routing/autopilot.Config:LEWAY_ENABLED (bool): Toggle modeling.LEWAY_METHOD ("simple" | "visir2"): Model variant; current implementation supports only "simple".LEWAY_K (float): Scaling coefficient controlling magnitude.LEWAY_MAX_DEG (float): Absolute clamp for leeway degrees.API: see backend/app/modules/leeway_model.pyestimate_leeway(wind_speed_kn, boat_speed_kn, rel_wind_deg, *, method=None, k=None, max_deg=None) -> floatMath (simple):Let AWA = relative wind angle (deg) ∈ [-180, 180].s = sin(AWA); magnitude = K * (wind^2 / max(boat_speed, eps)) * |s|; sign = sign(s); result clamped to ±LEWAY_MAX_DEG.Notes:Zero at head/tail wind (0°, ±180°). Symmetric: f(+θ) = -f(-θ). Magnitude increases with wind and decreases with boat speed.Conventions: AWA starboard positive; return sign follows sin(AWA).Future: Add "visir2" empirical variant.Wind EstimatorPurpose: Smooth AWA/AWS and estimate gusts for more stable control inputs and display.Config:WIND_ESTIMATOR_ENABLED (bool): Toggle estimator.WIND_ESTIMATOR_METHOD ("ewma" | "window"): Smoothing approach.WIND_EWMA_ALPHA (float): EWMA alpha (0-1).WIND_WINDOW_SECONDS (float): Sliding window duration.WIND_GUST_PERCENTILE (float): Percentile for gust (e.g., 0.95).API: see backend/app/modules/wind_estimator.py`WindEstimator(method, ewma_alpha, window_seconds, gust_percentile)``add_sample(awa_deg, aws_kn, timestamp=None)`; `get_state()` → `{ awa_deg, aws_kn, gust_kn, method, window_size }`Math:AWA: circular mean via sin/cos accumulation (EWMA mode uses EWMA on components).AWS: EWMA or arithmetic mean in window; gust via percentile or window max (EWMA mode).Notes:Inputs: AWA in [-180, 180] deg (starboard +), AWS in knots.Cleanly degrades with no samples; pure function style for easy testing.Autopilot ControllerPurpose: Runs a background loop to compute rudder commands by combining `AutopilotPID`, smoothed wind (optional), and leeway bias (optional) using live Signal K data.Inputs: `navigation.heading`, `navigation.speed_through_water` (kn), `environment.wind_direction` (deg true), `environment.wind_speed` (m/s).Processing:AWA = wrap(`wind_direction` − `heading`), AWS = `wind_speed` × 1.94384.Optional smoothing via `WindEstimator` (config-gated).Optional leeway via `estimate_leeway()`; added to heading error to steer into wind.Calls `AutopilotPID.compute_rudder(xte, heading_error_eff, AWA, dt)` and clamps/deadbands.Outputs: Rudder degrees broadcast on WebSocket (`type: "autopilot"`), and forwarded to optional sinks (e.g., NMEA2000) when enabled.Config:`AUTOPILOT_*` (PID/limits), `LEWAY_*`, `WIND_*`, `AUTOPILOT_UPDATE_INTERVAL`.API Endpoints:GET `/api/v1/autopilot/status`POST `/api/v1/autopilot/enable` → `{ enabled: bool, desired_heading_deg?: number }`POST `/api/v1/autopilot/heading` → `{ heading_deg: number }`NMEA2000 Autopilot OutputPurpose: Encodes rudder angle and heading setpoint as NMEA2000 PGNs for optional CAN transmission to compatible devices.PGNs:127245 (Rudder): rudder angle in radians; payload 7 bytes.127250 (Vessel Heading): true heading in radians + rate; payload 8 bytes.Features:Graceful degradation: if python-can unavailable, output is silent (no errors).Configurable CAN interface and bitrate.Status endpoint for debugging.Config:NMEA2000_INTERFACE (default "can0"): CAN bus device.(bitrate hardcoded to 250 kbps in module).API: see backend/app/modules/nmea2000_autopilot_out.py`NMEA2000RudderCommand.encode(rudder_deg)` → 7-byte payload.`NMEA2000HeadingCommand.encode(heading_deg, rate_deg_s)` → 8-byte payload.`NMEA2000AutopilotOutput.send_rudder(deg)`, `send_heading(deg, rate)`.Integration: Wired to `AutopilotController` via optional output_sink callback during setup.Track ControlPurpose: Compute cross-track error (XTE) from current position and desired waypoint leg;
